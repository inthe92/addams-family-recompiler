## Contract selected before implementation

Existing timed bus accesses retain their zero-based offsets and all device
events. CPU cycles are committed once by `advance(total)`. The APU flag and
`irq_pending()` source retain their existing behavior, including status clearing.

The bus keeps eight timestamped **detector samples**, sufficient for the longest
official instruction. When advancing from device time T to T+1, it records the
current IRQ source *before* clocking the next APU cycle. This explicitly models
one cycle of level-detector history in the integer-clock convention, independently
of the newly advanced readable flag. There is no extra bus read, no shifted APU
event, and no clock added. A read/write at T can affect the next sample, but
cannot rewrite a sample already taken. This mapping must pass both PAL 08
alignments; it is not an assertion of a measured get/put or phi phase.

At instruction completion the generated code supplies its duration and a bitset
of detector-poll offsets. For ordinary instructions the bit is `total-1` (the
saved level comes from `total-2` in this bus's completed-time convention).
Branches poll at offset 1 whether taken or not; a taken page-crossing branch
additionally polls at offset 3. Either sample can decide IRQ. BRK does not poll
for another IRQ. Page penalties therefore influence ordinary polls, while an
extra taken-branch cycle does not move its first poll. The guarded RAM JMP uses
the ordinary three-cycle plan. Nothing decodes instruction bytes at runtime.

CLI/SEI/PLP use the existing pre-instruction I mask; RTI uses restored I.
The bus reconstructs a decision only from the instruction's timestamped samples,
then `boundary` consumes it exactly once with that mask. It does not recheck the
live source to cancel or invent this decision. DMA may advance devices but does
not replace the completed instruction's poll. A newly asserted IRQ during DMA
is eligible at a subsequent instruction poll. This is the existing coarse
fetch-boundary DMA model, not certification of halt/get/put races.

An already latched NMI keeps priority and discards that instruction's IRQ
decision. The next instruction must sample again; there is no permanent latch.
NMI's own edge timing/vector hijacking is not redesigned here. Direct diagnostic
calls to `Bus::boundary` without a generated poll retain their existing live-source
behavior; production generated instructions always supply a poll descriptor.

## Compatibility and alternatives

Append a `poll_irq(context,total,offset_bits)` service. This is a semantic and
binary contract change: bump ABI **2 to 3**, reject v2 modules, and require
reimport/regeneration of their local C/modules. Cache identity already hashes
the ABI/service/emitter files and requires the current ABI receipt. Add explicit
v2 rejection and cache-regeneration cases while retaining missing/v1 checks.
CPUState and data access callbacks do not change.

Rejected: live-source boundary polling (loses decisions and accepts late IRQ),
an everlasting pending flag (stale/spurious IRQ), duration-only inference
(three-cycle JMP and taken BNE differ), runtime ROM decoding, moving all APU
events, special checks for 33252, and a CPU/scheduler rewrite.

## Cause, implementation and files

The earlier bus examined a **live source only after completion**, admitting
late assertions and losing earlier samples cleared by a final read. Instruction
duration alone also cannot distinguish a taken noncrossing branch from JMP.
The correction retains timestamped detector samples and transports the static
poll plan instead of reconstructing a decision from the final source.

## ABI/cache outcome and regeneration

ABI v2 binaries are rejected by the existing loader before executing their entry
point; the user receives `Native module ABI mismatch: 2; required 3. Reimport ROM
with current tools.` A missing ABI and v1 remain rejected. The real loader tests
executed on this host prove rejection; the cache test proves a v2 receipt cannot
reuse a matching synthetic cache marker. Current matching v3 cache reuse passes.

The importer's existing identity hashes the emitter, headers and profile and
requires the current ABI number. No cache protocol rewrite is needed: a normal
reimport generates fresh C, resources and module locally from the user's ROM.
Do not manually rebuild stale generated C against the new headers: regenerate
all sources with the current emitter. Unchanged structure size would not suffice;
both the added callback layout and branch semantics are incompatible. Neither a
commercial import nor an old private cache is executed or deleted in this task.

## Limits, risks and remaining A02

- **A02 still fails unchanged**: fresh anchor 33249, read offset 3 at 33252,
  returned `$40`, immediate live source 0, existing expected source 1. No test
  exception or retention guard is added. Closing CPU polling does not resolve
  the status-latch/source/CPU-line collision contract.
- PAL 07/08 are authored program equivalents of published tests whose author
  reports PAL hardware success. They provide program-level acceptance, not our
  own measured get/put, M2 or phi traces. The integer detector mapping is bounded
  by this evidence; exact simultaneous status-clear/assert/inhibit phases remain
  unverified.
- Existing NMI edge collection and vector hijacking limits remain. The new
  priority test confirms a pending NMI discards the sampled IRQ, with no stale
  delivery after RTI; it does not certify every NMI arrival phase inside an IRQ.
- OAM/DMC tests check the current **instruction-boundary stall model**, its clock
  totals/copy and preserved decisions. In-cycle CPU halt/repeated reads,
  cancellation races and OAM/DMC overlaps are not newly certified. An IRQ arising
  only during a stall does not retroactively change the completed instruction's
  poll; this is explicitly a runtime-contract control.
- History retains only the instruction window, not an unbounded pending IRQ.
  Invalid descriptors/timestamps and unconsumed decisions raise logic errors.
  Calls to manual diagnostic `boundary` keep their historical live-source path;
  every actual desktop adapter now forwards the native v3 service.
- Per-cycle collection adds bounded history work; device cycle counts and tested
  PCM behavior remain correct. No comparable performance benchmark was run.
- Windows, Linux and Intel execution of this change is pending. No CI claim,
  private-ROM playthrough or publication is made.

Recommended next step: define and independently validate A02's separate PAL
readable-flag/source collision observable before altering its test or APU.
No speculative same-cycle retention fix is recommended merely to make CI green.
